# 应用层安全隧道 —— 抓包样例

> 目的：证明敏感请求 Body 在网络上只以「数字信封」形式出现，明文（用户名、密码等）不会泄露。

## 1. 复现方式

- **浏览器 DevTools**：F12 → Network → 发起登录 → 查看 Request Payload。
- **Burp Suite / Fiddler**：设置系统代理，拦截 `POST /api/login`。
- **Wireshark**：过滤 `http.request.method == "POST"`，展开 HTTP Body（抓本机回环流量需选择 loopback 网卡）。

## 2. 若未加密，抓包会看到（对比）

```json
{"username":"admin","password":"admin123"}
```

## 3. 实际线上信封报文（真实运行样例）

```json
{
  "enc": "sm2-sm4-gcm",
  "v": 1,
  "ts": 1791352133019,
  "nonce": "fU/syxNSIbDlQDnn",
  "ek": "411678696063c6c1197e01d0a23345a104d02ad7fa2d5628c20ab89bafc580336996a951e4ead3f629961ec1ebbfc70c43fc056a1b16f24afe5679c0a412ad06c7566aa2e8a4021f96e35400cde9f342b3c7a22837a9efb20b7738986f9e9a7c9ef5686c768f02b3dbdd491883877f67",
  "ct": "wD1+0fs9jtWIXE+43AQ92eZJiSUSK7jGfvsR9oIYGdfRDfgVG5Cq9FxC",
  "tag": "93axOaNNZFlsF8u3LW3N1g=="
}
```

> 注：`nonce` / `ek` / `ct` / `tag` 每次请求均随机（nonce 与会话密钥由 CSPRNG 生成），上表为一次真实运行的输出。

## 4. 字段说明

| 字段 | 值样例 | 说明 |
| --- | --- | --- |
| `enc` | `sm2-sm4-gcm` | 算法标识 |
| `v` | `1` | 协议版本 |
| `ts` | `1791352133019` | 毫秒时间戳 |
| `nonce` | `fU/syxNSIbDlQDnn` | 96 bit 随机数（Base64） |
| `ek` | `411678...877f67` | SM2 封装的会话密钥 |
| `ct` | `wD1+0fs9...C9FxC` | SM4-GCM 密文 |
| `tag` | `93axOaNN...N1g==` | GCM 认证标签 |

## 5. 校验结果（真实运行断言）

- 线上报文包含明文密码 `admin123` ？ → **false** ✅
- 线上报文包含字段名 `"password"` ？ → **false** ✅
- 服务端解封还原出 `{"username":"admin","password":"admin123"}` ？ → **true** ✅（往返一致）

## 6. 结论

抓包层面只能看到信封的 7 个字段，无法获得明文用户名 / 密码等敏感信息：

- 密文的**机密性**由 SM4-GCM 认证加密保证；
- **完整性 / 抗篡改**由 GCM tag 保证；
- **重放**由 nonce + 时间窗阻断。

完整协议细节见《数字信封加密协议说明》。

> 提醒：应用层加密只保护 Body；URL、Header 与响应在无 HTTPS 时仍为明文，生产环境必须叠加 HTTPS。
