# 应用层安全隧道 —— 数字信封加密协议说明

> 所属项目：优选商城（电商平台）
> 协议标识：`sm2-sm4-gcm`（版本 `v1`）
> 适用范围：携带 JSON Body 的敏感请求（POST / PUT / DELETE）

## 1. 设计目标

在不改造底层 TLS 的前提下，对携带 JSON Body 的敏感请求做**应用层加密**，提供：

- **机密性**：Body 明文（如密码、订单、个人信息）不出现在网络报文中；
- **完整性 / 抗篡改**：SM4-GCM 认证标签保证密文与 AAD 未被篡改；
- **抗重放**：nonce + 时间窗双重校验，防止同一请求被重放；
- **密钥封装**：SM2 非对称封装随机会话密钥（数字信封），实现会话密钥的安全传输。

## 2. 威胁模型与安全边界

| 能力 | 是否覆盖 | 说明 |
| --- | --- | --- |
| 保护 Body 机密性 | ✅ | SM4-GCM 认证加密 |
| 保护 Body 完整性 / 防篡改 | ✅ | GCM tag + AAD 绑定 |
| 防重放 | ✅ | nonce 去重 + ±5 分钟时间窗 |
| 服务器身份认证 | ❌ | 需 HTTPS/TLS |
| 前向保密 | ❌ | 需 TLS（临时密钥协商） |
| 公钥分发安全 | ❌ | 公钥需经 HTTPS 下发或预置 pinning |

> ⚠️ **本机制不能替代 HTTPS。** 它只保护 Body，不提供服务器身份认证、前向保密与密钥的安全分发。生产环境必须叠加 HTTPS；SM2 私钥经环境变量 `SM2_PRIVATE_KEY` 注入或托管于 KMS/HSM，公钥经 HTTPS 下发或预置并定期轮换。

## 3. 算法与参数

| 项 | 值 |
| --- | --- |
| 会话加密 | SM4-GCM（128 bit 密钥，CTR 流加密 + GHASH 认证） |
| 会话密钥 | 128 bit 随机（CSPRNG） |
| Nonce / IV | 96 bit 随机，GCM IV，兼作重放去重 |
| 认证标签 | 128 bit |
| 密钥封装 | SM2（C1C3C2 编码），封装会话密钥 |
| AAD | `enc|v|method|path|ts|nonce`（绑定请求上下文） |

## 4. 信封结构

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `enc` | string | 固定 `sm2-sm4-gcm` |
| `v` | number | 协议版本 `1` |
| `ts` | number | 客户端时间戳（毫秒），用于时间窗校验 |
| `nonce` | string | Base64 的 96 bit 随机数 |
| `ek` | string | SM2 加密后的会话密钥（数字信封，hex C1C3C2） |
| `ct` | string | Base64 密文 |
| `tag` | string | Base64 的 GCM 认证标签 |

## 5. 加密封装流程（客户端）

1. 生成随机会话密钥 K（128 bit）与 nonce（96 bit）；
2. 构造 AAD：`sm2-sm4-gcm|v1|METHOD|PATH|ts|nonce`；
3. 用 SM4-GCM 以 K 加密 JSON 明文，得到 `ct` 与 `tag`；
4. 用服务端 SM2 公钥加密 K，得到 `ek`；
5. 发送 `{enc, v, ts, nonce, ek, ct, tag}`。

> 关键实现：`client/src/api/envelope.js`（`sealBody`）、`client/src/api/sm4gcm.js`（`gcmEncrypt`）、`client/src/api/index.js`（fetch 封装层对 POST/PUT/DELETE 统一加密封装）。

## 6. 解封解密流程（服务端）

1. 中间件识别 `enc === 'sm2-sm4-gcm'`（非信封请求原样放行，兼容明文）；
2. 时间窗校验（|now − ts| ≤ 5 分钟）→ 重放校验（nonce 未见过）；
3. 用 SM2 私钥解封会话密钥 K；
4. 用 K 做 SM4-GCM 解密并校验 tag；
5. 还原 JSON 对象，放回 `req.body`，进入业务路由。

> 关键实现：`server/src/middleware/envelope.middleware.js`（解密中间件，挂在 `express.json()` 之后、业务路由之前）、`server/src/services/envelope.js`（`openEnvelope`）、`server/src/services/sm4-gcm.js`、`server/src/services/replay.js`。

## 7. AAD 设计

AAD 把密文绑定到 `算法|版本|方法|路径|时间戳|nonce`，防止密文被搬移到其它接口（跨请求 / 跨路径复用）或篡改 `ts` 后复用。任一字段变化都会导致 GCM tag 校验失败。

## 8. 时间窗 + 重放防护

- 时间窗：±5 分钟（`WINDOW_MS = 5 * 60 * 1000`）；
- 重放：`nonce` 单进程内存去重（Map），且只在**解密成功后**才记录，避免无效请求污染缓存；
- 单机部署足够；多实例部署需替换为共享存储（如 Redis）。

## 9. 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| `EXPIRED` | 400 | 时间窗过期或提前于服务器时间 |
| `REPLAY` | 409 | 检测到重放请求 |
| `BAD_ENVELOPE` | 400 | 非信封 / 字段缺失 / 协议版本不符 / 明文非合法 JSON |
| `DECRYPT_FAILED` | 400 | SM2 数字信封解封失败 |
| `INTEGRITY_FAILED` | 400 | 密文解密或完整性校验失败 |
| `BAD_TIMESTAMP` | 400 | 缺少或非法时间戳 |
| `BAD_NONCE` | 400 | nonce 非法 |
